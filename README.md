# 轻存 · TikTok 视频下载器

**粘贴链接、加入队列、保存到本机，并看清每一项的结果。**

下载单条视频本身并不复杂，反复整理一批链接时才会遇到那些烦人的细节：同一个作品被加了两次、一个失败任务影响后续队列、工具退出成功却找不到文件，或者系统代理已经可用还要重复配置。

轻存是一个面向 Windows 的 Electron 桌面工具，将手工提交的 TikTok 单视频链接交给 yt-dlp 处理。界面管理输入与结果，主进程管理队列、下载进程、设置和代理。任务运行时可以继续添加链接，保存目录留在本机。

## 从链接到文件

```text
粘贴单视频链接
  → 解析、校验与去重
  → 加入桌面队列
  → 解析系统代理路线
  → 启动 yt-dlp 子进程
  → 读取进度与结果
  → 核对输出文件
  → 完成 / 失败 / 取消等逐项状态
```

主页、直播与无关站点不是当前链接入口的目标。短链接与最终作品可能对应同一个视频，队列还会处理解析后的重复身份，不能只比较粘贴的字符串。

## 队列里需要区分哪些状态

| 状态或操作 | 作用 |
| --- | --- |
| 等待 | 链接已经接收，尚未开始下载 |
| 启动 / 下载中 | 子进程与当前进度正在更新 |
| 完成 | 进程结果与目标文件满足完成条件 |
| 失败 | 保留业务提示与受限技术信息 |
| 取消 | 区分用户停止与下载器报错 |
| 重复 | 已有相同作品，避免重复保存 |
| 重试 | 将可重试项目重新加入队列 |

恢复已保存任务时，原先仍在启动或下载中的项目重新进入等待；标为完成却没有有效输出文件的记录，不能继续展示成完整成品。这些行为集中在 `download-manager.js`。

文件路径需要落在本次下载目录中，成功判定还要检查输出文件。仅有退出码 0，不足以证明得到了预期 MP4。

## 系统代理与失败提示

代理模块读取 Electron 提供的系统路线，处理直接连接、代理及 PAC 解析结果。下载队列据此组织尝试路线，并针对明确的连接失败处理后续候选。

代理连接问题、代理认证问题、平台权限和 HTTP 拒绝不是同一类错误。技术信息在展示前做长度限制与脱敏，避免直接把本机代理地址和完整异常文本当成普通界面文案。

网络可访问不代表平台一定允许下载；登录、地区、风控和资源失效需要按实际错误判断。

## 为什么把界面与下载进程分开

| 模块 | 职责 |
| --- | --- |
| [main.js](src/main.js) | Electron 主进程与应用生命周期 |
| [preload.js](src/preload.js) | 向界面暴露受限 IPC 接口 |
| [renderer/](src/renderer/) | 链接输入、队列和设置界面 |
| [link-parser.js](src/lib/link-parser.js) | 支持链接、校验与去重 |
| [download-manager.js](src/lib/download-manager.js) | 子进程、状态、恢复与输出核对 |
| [proxy-resolver.js](src/lib/proxy-resolver.js) | 系统代理候选 |
| [settings-store.js](src/lib/settings-store.js) | 本地设置保存 |

界面不会直接取得任意系统进程执行入口。下载状态由主进程维护，避免把文件操作散在 UI 事件中。

## 开发准备

```powershell
pnpm install
pnpm test
pnpm run check
```

运行与打包前，需将 **yt-dlp 2026.08.19 的 Windows 可执行文件**放到 `vendor/yt-dlp.exe`。此处是项目采用的固定版本，不是最新版本声明。仓库保留对应 SHA-256 和许可，二进制需从 yt-dlp 官方发行资源自行取得。

```powershell
pnpm run verify:engine
pnpm start
pnpm run dist
```

`verify:engine` 实际核对版本与哈希，版本变更需要同步维护记录。`dist` 配置输出 Windows x64 便携程序到 `release/`，打包链会把下载引擎与许可放入相应资源位置。

建议在开发环境先检查链接解析、引擎核对和一项实际下载，再尝试批量任务与打包。下载引擎正常启动，不代表所有平台条件已满足。

## 一次使用应该检查什么

将有权处理的单视频链接加入队列，选择自己的保存目录，观察逐项进度。完成后打开目标文件核对内容；失败时先看是哪一项、停在哪一层，再决定重试。

本机设置与任务恢复属于个人运行状态，不应随源码分享。公开版本没有浏览器登录态、真实下载记录和视频成品。
